# Деплой на Cloudflare Pages (Vite + React)

## Ошибка `main.tsx` и MIME type `null` (или неверный тип)

В **исходном** `index.html` в корне репозитория указано:

```html
<script type="module" src="/src/main.tsx"></script>
```

Это **нормально для разработки** (`npm run dev`): Vite сам обрабатывает TSX.  
Если на хостинг залить **не собранный проект** (корень репозитория с `src/`, без `npm run build`), браузер запросит `/src/main.tsx`. Обычный статический сервер отдаст файл **без** корректного `Content-Type` для ES-модуля → в консоли: **Failed to load module script** и MIME **`null`** (или `text/plain`). Плюс **белый экран**.

**Решение:** всегда публиковать **только результат `vite build`** — папку **`dist`**, где `index.html` уже ссылается на **`/assets/index-<hash>.js`**, а не на `main.tsx`.

## Почему бывает белый экран и ошибки MIME `text/html` для JS/CSS

Сервер отдаёт **index.html** вместо реального файла. Тогда браузер ждёт JavaScript/CSS, а получает HTML → ошибки в консоли про MIME type.

Чаще всего это **не баг React**, а то, что в корне деплоя **нет** папки `assets/` и файлов из свежей сборки (неверный **Build output directory**, загрузка архива с лишним уровнем вложенности, старый билд и т.д.).

## Что должно оказаться в корне публикации (содержимое `dist/`)

После `npm run build` откройте папку `dist` — **именно её содержимое** должно стать корнем сайта:

```
index.html
favicon.svg
assets/
  index-<hash>.js
  index-<hash>.css
  ... (другие чанки)
```

Имена `index-*.js` / `index-*.css` меняются при каждой сборке; важно, чтобы на CDN лежала **та же** сборка, что и в вашем локальном `dist` (один прогон `npm run build` → один upload).

## Настройки Cloudflare Pages (Git-интеграция)

| Поле | Значение |
|------|----------|
| Build command | `npm run build` |
| Build output directory | `dist` |

**Важно:** в поле output указывают **`dist`**, а не `dist/dist`, не корень репозитория и не путь к архиву «с обёрткой». Cloudflare должен взять **файлы внутри** `dist` и положить их в корень `*.pages.dev`.

Если репозиторий — монорепо и проект в подпапке, задайте **Root directory** на эту подпапку (где лежит `package.json` этого приложения), затем по-прежнему **Build output directory: `dist`**.

## Прямая загрузка (Direct Upload / архив)

- Упаковывайте **содержимое** `dist`, а не саму папку `dist` как единственный элемент так, что сайт оказывается на `.../dist/index.html`, а запросы идут на `/` и `/assets/...` мимо этих файлов.
- После распаковки архива в корне должны лежать `index.html`, `favicon.svg`, каталог `assets/`.

## Проверка после деплоя

1. Сайт открывается, не белый экран.
2. DevTools → Network: запросы к `/assets/*.js` и `*.css` — **200**, тип **javascript** / **css**, не `document`.
3. В консоли нет: `Expected a JavaScript-or-Wasm module` / `stylesheet MIME type ('text/html')`.

Быстрая проверка вручную: откройте в браузере `https://<ваш-проект>.pages.dev/assets/<имя-файла-из-index.html>.js` — должен отображаться/скачиваться JS, а не HTML-страница.

## Конфигурация Vite в этом проекте

В `vite.config.ts` задано `base: '/'` — это соответствует публикации с корня домена на Pages. Меняйте `base` только если сайт реально отдаётся с подпути (например `example.com/app/`), и тогда подпуть должен совпадать с `base`.
